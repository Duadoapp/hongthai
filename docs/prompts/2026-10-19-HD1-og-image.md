# HD1：每個機場一張分享預覽圖（og/<iata>.png）

模型：Opus，強度高。規格是 Duado #374 定的（Shawn 2026-10-18 轉述）；這支只加輸出，不碰 `latest.json`。

先讀 `docs/ORCHESTRATOR.md`（定位、階段清單 HD1 那條）、`README.md`、`src/hongthai/build.py`（`publish()`、
`Timing`、`BUDGET_S`）、`src/hongthai/assess.py` 開頭（等級）、`airports.json`。

## 規格（Duado #374 定案）

每報 build 跑完，用 **Pillow** 畫每個機場一張 **1200×630** 的分享預覽圖，發布到 GitHub Pages 的
`og/<iata>.png`（iata **小寫**，例如 `og/tpe.png`）。內容：IATA 大字、機場名（zh-TW＋en）、燈號
（AI 上線前一顆規則燈，上線後自動變三顆）、更新時間、HongThai 字樣。字型由 hongthai 自備（OFL 授權的中日韓
字型放在 repo，附授權檔）；Duado 用 Pages Function 轉送這張圖，網址格式他們知道，`latest.json` 不用加欄位。

## 預設值（主對話替 Shawn 先定的，Shawn 會確認；有改會寫在這一節）

1. **燈號代表什麼**：這個機場**未來 5 天（20 格）裡最高的等級**；旁邊一行小字寫第一個達到那個等級的格的
   當地日期時段，例如「最高：高　10/23 14–20 時」；全部低就寫「未來 5 天：低」。`confirmed` 的格視為高，
   並寫「已確認停飛」；全部 `unknown` 時燈灰色、寫「資料不足」
2. **燈的顏色**：低 `#16A34A`、中 `#F59E0B`、高 `#DC2626`、未知 `#9CA3AF`（先用這組；Duado 網頁的色碼
   Shawn 給了就換成一樣的，顏色集中寫在一個 dict）
3. **底色**：白底深字（`#111827`），分享卡在深色、淺色的社群 App 裡都看得清楚；不做深色版
4. **字型**：Google Fonts 的 **Noto Sans TC**（OFL 1.1），Regular 與 Bold 兩個字重。**不要把整套字型放進 repo**
   （一個字重就 7–8 MB）：用 fontTools 的 `pyftsubset` 做**子集**，只留 `airports.json` 裡所有 zh-TW 名稱、
   地區名、固定字串（「最高」「未來 5 天」「低」「中」「高」「已確認停飛」「資料不足」「更新」「機場停飛風險」
   「規則」「時」等）、數字、ASCII、全形標點、`–`／`・` 的字；子集檔放 `assets/fonts/NotoSansTC-Regular.subset.ttf`、
   `…-Bold.subset.ttf`（各約 100–300 KB），旁邊放 `assets/fonts/OFL.txt` 與一個 `README.md` 寫來源、版本、
   怎麼重做。重做的腳本放 `tools/make_font_subset.py`（讀 `airports.json` 與固定字串，從完整字型產子集；
   完整字型從 Google Fonts 下載到暫存目錄，不進 repo）。**測試**用 fontTools 檢查子集涵蓋所有需要的字
   （之後 HD3 這類加機場的 PR 沒重做子集，CI 會紅）
5. **版面**（1200×630，邊距 64）：左上 IATA 大字（Bold，約 160 px）；其下機場名 zh-TW（Bold 56）＋ en（Regular 36）；
   右上燈號區：一顆直徑 120 的圓（之後三顆時並排、各自下方標「規則」「Claude」「Gemini」，寬度自動排）；
   燈下方那行小字（第 1 點）；左下「更新 2026-10-19 02:15（當地時間）」（Regular 28，用該機場的時區顯示
   `generatedAt`）；右下「HongThai　機場停飛風險」（Bold 32）＋ 一行小字「duado.app/hongthai」。
   不放 logo、不放地圖
6. **三顆燈的擴充**：畫圖的函式吃一個 `lights: list[Light(label, level, note)]`，現在只傳一顆（規則燈，`label`
   省略不畫）；AI 對決那支只要多傳兩顆，版面自動變三顆
7. **產出與失敗處理**：在 `publish()` 之後、Pages 上傳之前畫，寫到 `public/og/<iata>.png`；**不進 `data` 分支**
   （每報重畫，不留歷史）。畫圖失敗只 log、不讓 build 失敗；`history/timing/` 加一行 `source: "og"`
   （`ok`、`seconds`、`bytes` 是 51 張的總大小）；預算 60 秒（`BUDGET_S["og"]`）。整次 build 失敗改發布上一份
   `latest.json` 時，也用那份重畫（和 `publish(prev)` 同一條路）
8. **PNG 大小**：目標每張 ≤ 60 KB（白底、少色，`optimize=True`；需要的話轉成調色盤模式）。51 張約 3 MB，
   Pages artifact 可以接受

## 要做的事

- `pyproject.toml` 加 `pillow`（執行）與 `fonttools`（執行，子集涵蓋測試要用；`tools/` 腳本也用它）
- 新模組 `src/hongthai/og.py`：`render(airport_json, generated_at, lights, out_path)`（純畫圖，不讀網路）＋
  `render_all(latest, out_dir)`（從 `latest.json` 的內容算每個機場的燈與小字、逐張畫）
- `build.py`：`publish()` 之後呼叫 `render_all`，接 timing 與預算
- `build.yml`：不用改（`public/` 整個上傳）
- `assets/fonts/`、`tools/make_font_subset.py`、`tests/test_og.py`（51 張都畫得出來、尺寸 1200×630、每張 ≤ 60 KB、
  一顆與三顆燈的版面都不出錯、子集涵蓋所有需要的字、燈號與小字的規則）
- README：加「分享預覽圖」一節（網址、內容、字型授權與怎麼重做子集）；「資料來源與授權」表加 Noto Sans TC
  （OFL 1.1）；ORCHESTRATOR 的「流程」與「`data` 分支」說明同步（`og/` 只在 Pages）
- 不要動 `assess.py`、`cancellations.py`、各來源

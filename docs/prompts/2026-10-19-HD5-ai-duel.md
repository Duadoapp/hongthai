模型：Opus，強度高。這支接外部 API、花錢，**金鑰只從環境變數讀、程式與測試裡不能出現任何金鑰**；測試不連網。

## 定案（Shawn 2026-10-18／19）

1. 三顆燈：規則（現有等級）、Claude Opus 5.5、Gemini 4 Argon 各一顆。兩個 AI **各自**讀該機場的全部數據，給自己的
   等級（低／中／高）＋一段短評，像評論員；數據照舊全部保留給讀者
2. **只請 AI 評「未來 5 天有任一格 ≥ 中、或等級有變」的機場**；其他機場兩個 AI 燈直接寫「沒看到明顯風險」，不呼叫。
   「等級有變」＝和上一份 `latest.json`（`previous_latest`）比，任一格的 `level` 不同
3. 短評一次輸出四語（zh-TW、zh-HK、zh-CN、en），**以 zh-TW 為準、其他三語是忠實翻譯，四語內容必須完全一樣、
   不得增減**；zh-HK、zh-CN 用當地用語
4. AI **只能根據 `latest.json` 裡的數據講**，不能自己生機率數字、不能引用外部資訊；附免責「AI 評論僅供參考，
   以航空公司與機場公告為準」
5. 記「對決戰績」：每報把三方等級存進 `data` 分支，11/18 用停飛統計回看誰事前比較準
6. 金鑰：HongThai 專屬、各月上限 30 美元、不跟 Duado 共用；只放 Actions secrets
7. 程式內保險：每報最多評 20 個機場（超過先評 5 天內最高等級高的）、每天每個模型最多 80 次呼叫、格式不對或逾時
   記 `error` 不重試、AI 來源預算 180 秒（兩個模型**平行**呼叫）

## 金鑰與模型（環境變數；Shawn 放在 Actions secrets）

| 環境變數 | 內容 |
| --- | --- |
| `ANTHROPIC_API_KEY` | Claude Console「HongThai」Workspace 的金鑰 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | GCP 服務帳號金鑰 **JSON 整份原文**（不是 base64）；程式用 `json.loads` 讀、再交給 `google.oauth2.service_account.Credentials.from_service_account_info`，不寫到磁碟 |
| `GOOGLE_CLOUD_PROJECT` | GCP 專案 ID |
| `GOOGLE_CLOUD_LOCATION` | `global`（Argon 只開 global、us、eu，沒有 asia） |

- Claude：模型 `claude-opus-5-5`，用官方 `anthropic` Python SDK，Messages API，`max_tokens` 1200；用 `temperature` 0.3
- Gemini：模型 `gemini-4-argon`，**走 Vertex AI**（`google-genai` SDK，`vertexai=True`、`project`、`location="global"`、
  `credentials` 用上面的服務帳號），`max_output_tokens` 1200、`temperature` 0.3；回應要求 JSON（`response_mime_type`
  `application/json`）
- 少任一個環境變數：該模型 `status: "error"`、`error: "no_api_key"`，不呼叫；另一個照跑
- 模型字串、免責四語、每報上限、每日上限集中在 `src/hongthai/ai/config.py`（或同一處），之後換模型只改那裡
- `pyproject.toml` 加 `anthropic`、`google-genai`、`google-auth`；版本先用當下最新的穩定版並固定最低版本

## 要做的事

### 1. 新套件 `src/hongthai/ai/`

- `select.py`：`candidates(latest, prev) -> list[airport]`——未來 5 天任一格 `level` 在 `medium`／`high`／`confirmed`，
  或和 `prev` 同機場同 `from` 的 `level` 不同；依「5 天內最高等級（confirmed > high > medium > low）、再依第一個
  達到那級的格越早越前」排序，取前 20 個；回傳也要附每個機場被選的原因（`"level"`／`"changed"`，記進戰績）
- `prompt.py`：把一個機場的 `latest.json` 片段整理成給模型看的**精簡文字**（不要整段 JSON 丟進去）：機場名、
  時區、20 格每格的當地時段、`level`、`basis`、官方（TAF 陣風／平均風、側風、警報）、模式（EC 陣風、GFS 陣風、
  側風、`p29Kt`／`p49Kt`）、`agreement`、`gap`、METAR、生效中的警報、`confirmed`；單位一律節、機率用百分比。
  加上規則的門檻（37／48 節、側風 27／33、`p49Kt` 30%）讓模型知道「規則燈」是怎麼來的
- `prompt.py` 的系統提示（中文寫，模型回 JSON）：你是航空氣象評論員；只能用給你的數據，不能用其他知識或
  外部資訊、不能自己估機率；給一個等級 `low`／`medium`／`high` 與一段 **60–120 字（zh-TW）** 的短評，說明依據
  哪幾格、哪些數字；短評先寫 zh-TW，再把**同一段**忠實翻成 zh-HK（香港用語，例如「颱風信號」「停飛」）、zh-CN
  （大陸用語，例如「航班取消」「台风」）、en；四語**內容完全一樣、不得增減**；回 JSON：
  `{"level": "...", "comment": {"zh-TW": "...", "zh-HK": "...", "zh-CN": "...", "en": "..."}}`，不要其他文字
- `claude.py`、`gemini.py`：各一個 `evaluate(text) -> {"level", "comment"}`，逾時 60 秒（單次請求）；回來的 JSON
  解析失敗、`level` 不在三種裡、四語有缺或任一語超過 400 字 → 丟 `AiError("bad_format")`；HTTP／SDK 錯誤 →
  `AiError("http_<碼>"` 或 `"network")`；**不重試**
- `run.py`：`evaluate_all(latest, prev, now, history) -> dict`——
  - 選機場 → 兩個模型各自用 `ThreadPoolExecutor`（每個模型 4 條並行，兩個模型同時跑）評每個機場
  - **每日上限**：`history/ai/calls-<YYYY-MM-DD>.json`（UTC 日期）記每個模型今天呼叫了幾次，超過 80 次的機場記
    `status: "error"`、`error: "daily_cap"`；每次呼叫（成功或失敗）都算一次
  - 沒被選的機場：兩顆燈 `status: "skipped"`、`level: "low"`、`comment` 是程式寫死的四語「沒看到明顯風險」
    （zh-HK「未見明顯風險」、zh-CN「未见明显风险」、en「No notable risk seen」）
  - 回傳要寫進 `latest.json` 的 `ai` 結構與每個機場的 `airports[].ai`（見第 2 節）
- 整個 AI 步驟在 `build.py` 走 `_call("ai", ...)`，預算 180 秒（`BUDGET_S["ai"]`），超時的機場記 `error: "timeout"`；
  AI 失敗**不影響** `latest.json` 其他內容；timing 多一行 `source: "ai"`（`bytes` 放呼叫次數：`{"claude": n, "gemini": n}`
  改放在 `calls` 欄位，`bytes` 填 0）

### 2. `latest.json` 欄位（照 Duado spec 第 16 節；下面是定稿的結構）

- 頂層 `ai`：
  ```json
  { "disclaimer": { "zh-TW": "AI 評論僅供參考，以航空公司與機場公告為準", "zh-HK": "…", "zh-CN": "…", "en": "…" },
    "models": { "claude": "claude-opus-5-5", "gemini": "gemini-4-argon" } }
  ```
- `airports[].ai`：
  ```json
  { "evaluatedAt": "2026-10-19T02:15:00Z" | null,
    "claude": { "status": "ok"|"skipped"|"error", "level": "low"|"medium"|"high"|null,
                "comment": { "zh-TW": "…", "zh-HK": "…", "zh-CN": "…", "en": "…" } | null,
                "model": "claude-opus-5-5", "error": "<代碼>" (只有 error 時) },
    "gemini": { 同上 } }
  ```
  `skipped`：`level: "low"`、`comment` 固定四語；`error`：`level: null`、`comment: null`、`error` 代碼
  （`no_api_key`／`timeout`／`bad_format`／`http_<碼>`／`network`／`daily_cap`）；`evaluatedAt` 在 `skipped` 時也填
  （這一報的時間），兩顆都 `error` 時 `null`
- `sources.ai`：`{ "ok": <兩個模型至少一個有成功>, "seconds", "calls": {"claude": n, "gemini": n},
  "errors": {"claude": "<代碼>", ...}（只有失敗的） }`
- `tests/test_build.py` 契約測試加這些；README「輸出」補範例與說明；`docs/ORCHESTRATOR.md` 第四階段那條補
  「已實作」與檔案位置

### 3. 對決戰績（`data` 分支，不進 Pages、不進 `latest.json`）

`history/ai/<YYYY-MM-DD>.json`（UTC 日期，一天一檔、每報 append 合併，同 `cancellations` 的寫法）：每機場每跑次一筆
```json
{ "run": "2026-10-19T02:15:00Z", "airport": "RCKH", "selected": "level"|"changed"|null,
  "rule": { "maxLevel": "high", "firstFrom": "2026-10-23T00:00:00Z" },
  "claude": { "status": "ok", "level": "high" }, "gemini": { "status": "ok", "level": "medium" },
  "slots": [ { "from": "…", "level": "high" }, … 20 格只留 from 與 level ] }
```
只存等級與格，不存短評全文（短評在 `history/<時間>.json` 裡已有）。11/18 用它對 `history/cancellations/` 回看。

### 4. 預覽圖三顆燈

`og.render_all` 改成：該機場 `ai` 兩顆都是 `skipped` 或 `error` 時仍畫**一顆**規則燈（現狀）；任一顆 `ok` 時畫
**三顆**：`Light("規則", 規則等級, 規則小字)`、`Light("Claude", claude.level 或 "unknown", 短評不畫、小字留空)`、
`Light("Gemini", …)`；`error` 的那顆用 `unknown` 色塊寫「資料不足」、`skipped` 用 low。版面照 HD4 的三顆燈規則
（時間軸移到燈下方整排）。`og.TEXTS` 已有「規則」「Claude」「Gemini」「沒看到明顯風險」；確認子集涵蓋，不夠就重做
（`tools/make_font_subset.py`）

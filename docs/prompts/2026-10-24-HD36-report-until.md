## 定案（Shawn 2026-10-24 12:09、12:49 確認）

- 預報只算到 **10/25 14:00（台灣）之後的第一報**（16:25，08:25Z）
- 實測（METAR、颱風現報、航班）存到 **10/26 當天結束**（台灣 24:00＝10/26 16:00Z；`events.json` 已改 `to: 2026-10-26`）
- 兩個截止分開給參數；報告寫明兩個截止時間，以及**仍然沒有實測的筆數**（不算命中也不算誤報）
- AI 兩燈「每報每機場」的窗：**截到實測截止**為止，截止前有任一格停飛＝有停飛、都沒有＝沒停飛（颱風那時已經離開）；
  報告寫明幾個窗被截短，並附上**只算完整窗**的結果當對照。規則燈的「每格」照舊

## 1. 參數

- `--until <時間>`：預報算到「這個時間之後的第一報」——`generatedAt ≤ 時間` 的報全部算，再加上 `generatedAt > 時間` 的第一報；
  沒有這一報（還沒出）就只算到時間以前的，摘要寫「時間之後還沒有報」。不給＝全部的報（現在的行為）。
  WN3 的事件檔（`wn3/<起報>.json`）同一個規則，用起報時間
- `--truth-until <時間>`：實測只用到這個時間。不給＝`events.json` 那筆 `to` 的台灣日期隔天 00:00（`to: 2026-10-26` → 10/26 16:00Z）
- 時間格式：ISO 8601，要能讀 `Z` 與 `+08:00`；**`T24:00` 當成隔天 `T00:00`**（Shawn 寫的是 `2026-10-26T24:00+08:00`）。看不懂就印錯誤、回 1
- 實際用法（寫進 docstring 與 README）：

      python -m tools.report_29w --archive data --event 29W --jtwc bwp292026.dat \
        --until 2026-10-25T14:00+08:00 --truth-until 2026-10-26T24:00+08:00 --out report/29W.md --json report/29W.json

## 2. 實測截止怎麼套（`T`＝`--truth-until`）

實測的最後時間取 `min(T, 該資料本身最新的時間)`（例如航班統計的 `asOf`）。

- (a) 陣風：格的 `to` 晚於 `T` → 不算，計「超過實測截止」；`T` 以前但格內沒有 METAR → 照舊「沒有觀測」。METAR 本身也只用 `≤ T` 的
- (b) 每格：格的 `to` 晚於實測的最後時間 → 不算，計「超過實測截止」（和「沒有航班」分開計）
- (b) 每報每機場：窗裡 `to` 晚於實測最後時間的格**丟掉**（窗被截短，計一筆「截短」）；截短後一格都不剩 → 不算，計「沒有實測」。
  截短後照現在的規則比（任一格停飛＝有停飛；`first` 照截短後的窗算）。**另外算一份「只算完整窗」**（窗裡沒有任何格被丟掉的才算），
  兩份都印、都進 JSON
- (c) 路徑：真相（最佳路徑或現報）只用 `validAt ≤ T` 的點；模式路徑的點 `validAt > T` → 不算，計「超過實測截止」
- 版本切分（`--cutoff`）照舊

## 3. 報告寫明

- 摘要最上面：「預報算到：<最後一報的 generatedAt>（台北 …；`--until` …）」「實測到：<T>（台北 …）」，以及兩個截止各排除了幾報／幾筆
- 「資料完整度 › 跳過的」每一類多一欄「超過實測截止」；(b) 多「截短的窗」「截短後沒有實測」
- (b) 每報每機場的表：截短版是主表，「只算完整窗」放在下面當對照，標題寫清楚
- JSON：加 `until`（參數原值）、`lastReport`、`truthUntil`、各類「超過實測截止」與截短的計數、完整窗的那份統計；**原有欄位不改名**

## 4. 測試

- `--until`：剛好等於某報、介於兩報之間（要多算下一報）、之後沒有報；WN3 同規則
- `--truth-until`：`T24:00`、`+08:00`、`Z` 三種寫法；預設＝`events.json` 的 `to` 隔天 00:00（台灣）
- (a)(b)(c) 各一個「格／點跨過 T」的案例，計數正確、不算命中也不算誤報
- 每報每機場：窗被截短後有停飛／沒停飛、截短後空的、完整窗那份只收沒截短的
- 不給兩個參數時，輸出和現在一樣（用現有測試的 fixture 比）
